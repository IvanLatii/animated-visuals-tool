# Журнал рішень

Формат: дата — рішення — чому.

2026-10-21 — Стек: Vite + TypeScript (strict) + React, рендер через canvas 2D, GIF через gif.js (MIT), MP4 через Mediabunny (MPL-2.0) + WebCodecs — усе працює локально в браузері без сервера; gif.js дає дизеринг для градієнтів на скриншотах; Mediabunny замінила застарілий mp4-muxer; gifenc відкинуто, бо без дизерингу буде зі смугами.
2026-10-21 — Dev-залежності й gif.js/Mediabunny встановлено; React відкладено до каркаса — Іван вирішив тримати тест-прототип мінімальним.
2026-10-21 — Додано React, @vitejs/plugin-react і типи — Іван вирішив ставити React разом із каркасом.
2026-10-21 — Кадри в spike накладаються на час переходу (чорне блимання було помилкою в таймінгу) — перехід не додає часу до загальної тривалості.
2026-10-21 — Криві руху: тип + сила (степінь), для зуму за замовчуванням ease-out сила 3, для переходів ease-in-out сила 2 — Іван хоче швидкий старт і повільний кінець, лінійне не подобається; значення міняються через параметри.
2026-10-21 — Тривалість кадру за замовчуванням 1.0 с, перехід 0.3 с, зум 20% — Іван сказав, що 1.5 с / 0.5 с / 12% надто повільно.
2026-10-21 — renderScene(project, t, canvas, assets) має 4-й параметр assets (завантажені зображення) — малювання не може чекати на завантаження посеред кадру.
2026-10-21 — TypeScript зафіксовано на 6.0.3 (було 7.0.2) і додано ESLint (eslint, @eslint/js, typescript-eslint, eslint-plugin-react-hooks) — typescript-eslint не підтримує TypeScript 7; lint ловить помилки, які не бачить tsc. Папка spike у lint не входить.
2026-10-21 — Інтерфейс без бібліотек, простий CSS зі світлою й темною темою; перестановка кадрів вбудованим drag-and-drop браузера — менше залежностей; dnd-kit лише якщо перетягування буде незручним.
2026-10-21 — Експорт: MP4 основний формат, GIF там, де майданчик не приймає відео; режими «Максимальна якість / Збалансовано / Найменший розмір» + ручні налаштування — GIF має 256 кольорів і завжди більший за MP4 при схожій якості.
2026-10-21 — «Вмістити в N МБ»: ступінчасто від найменшої втрати якості (кольори → FPS → розмір), розмір не чіпаємо для Dribbble (рекомендовано від 1600 px); реальний фоновий експорт замість лише оцінки — точний розмір GIF наперед порахувати неможливо.
2026-10-21 — На початку кроку C — тест GIF-оптимізаторів (gif.js проти gifsicle/gifski) на реальних скриншотах; ліцензії й браузерна доступність ще ❌ не перевірені.
2026-10-21 — Новий шар за замовчуванням fit='fill' (картинка заповнює полотно, краї обрізаються); перемикач fit/fill — крок B.
2026-10-21 — Налаштування анімації мають дві області: «для всього проєкту» і «тільки кадр N» (перевизначення зі скиданням) — принцип брифу: розумні значення за замовчуванням і можливість змінити на рівні кадру.
2026-10-21 — fit/fill: Defaults.layerFit + необов'язкове Layer.fit; у кадровому режимі міняє всі шари кадру — модель шарова, але в версії 1 шар один.
2026-10-21 — Свій розмір полотна округлюється до парного числа, діапазон 64–4096 px — H.264 (MP4) не приймає непарних розмірів.
2026-10-21 — Safe-зона: рівний відступ з усіх боків (за замовчуванням 5%), показується тільки в прев'ю й не потрапляє в експорт.
2026-10-21 — Панорама й поворот у крок B не входять — за брифом вони «пізніше», за замовчуванням вимкнені.
